# 故障排查

## 启动或页面问题

- 确认 Zotero 是 9.x，插件已启用并完成重启。
- 若 `今日推荐` 显示“尚未配置”，进入设置完成 Embedding 测试；仅填写 LLM 不能启动画像。
- 若页面空白，打开诊断页导出默认诊断，优先检查任务状态、错误码和数据库迁移状态，不要先删除 Zotero 主数据库。

## 模型连接问题

| 错误码                            | 处理                                                                     |
| --------------------------------- | ------------------------------------------------------------------------ |
| `invalid-url`                     | 检查 Base URL 是否包含协议和正确的 `/v1` 前缀。                          |
| `insecure-url`                    | 远程服务改用 HTTPS。                                                     |
| `localhost-confirmation-required` | 只有确认本机回环 HTTP 服务可信时才勾选允许本机 HTTP。                    |
| `http-error`                      | 检查服务状态、模型名、Key 权限和配额；401/403 通常是认证或权限问题。     |
| `invalid-model-response`          | 检查 OpenAI-compatible 返回结构、向量数量、维数和有限数值。              |
| `empty-model-response`            | 检查 LLM 是否支持 Chat Completions；也可以关闭 LLM 回到 arXiv 原始摘要。 |
| `request-timeout`                 | 检查本机网络或本地服务是否休眠，必要时增大超时时间。                     |

任务详情中的 HTTP 错误会标明具体服务，例如 `arXiv 服务返回 HTTP 500` 或
`硅基流动返回 HTTP 500`。前者表示论文源站暂时不可用，后者表示模型服务暂时异常；先等待片刻
后点击“重试”，不需要重复创建画像或清空缓存。若 arXiv 持续 5xx，检查网络、代理和 arXiv
服务状态；若硅基流动持续 5xx，再检查模型可用性、额度和请求批大小。

arXiv 的日期筛选由插件使用 UTC 的 `YYYYMMDDHHMM` 格式生成。若任务详情仍显示旧的
`模型服务返回 HTTP 500`，请先安装包含服务来源诊断修复的新 XPI。

## 任务中断、失败和重复

任务中心中的 `interrupted` 必须由用户点击“继续”，`failed` 由用户点击“重试”；插件启动不会自动续跑。检查点只从最后一次成功阶段发布，重复点击不会重复创建相同的推荐或入库意图。

任务中心会显示开始时间、完成时间和耗时；推荐任务中的 `阶段 7/7` 表示七个处理阶段完成，
不是推荐论文数量。每条历史任务可以单独清除，标题栏的“一键清空”会清除全部历史任务，但会
保留排队和运行中的任务。清除只删除任务记录，不会删除推荐结果、兴趣画像、模型缓存或 Zotero 条目。

如果入库成功但 PDF 下载失败，先检查网络、HTTPS 重定向、Content-Type 和附件权限，再单独重试 PDF；核心 Zotero 条目不会被删除。重复保存同一 arXiv 版本会进入幂等检查，不会重复创建条目。

## macOS 锁屏与休眠

锁定屏幕本身通常不会停止 Zotero 进程；Mac 进入睡眠、网络断开或 Zotero 被退出则任务会暂停或中断。本插件没有后台定时器，推荐任务应在用户准备好后手动启动。需要长时间运行本地模型时，接通电源并在系统设置中暂时避免自动睡眠，完成后恢复个人安全设置。

## 数据库迁移

升级前备份 Zotero 数据目录。若迁移失败，保留诊断中的迁移错误码和备份信息，退出并重新打开 Zotero 后再重试。不要手工修改插件 SQLite；无法恢复时提供脱敏诊断和插件版本给维护者。
